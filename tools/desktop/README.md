# tools:desktop —— 桌面调试程序

在电脑（macOS、Linux）的 JVM 上直接连真手机，跑一次完整的有线投屏会话，把视频写成 H.264 文件。
用来在没有车机的情况下调试会话编排（`core:session`）和各协议层。只用于开发，不打进安装包。

**分工**：USB 拉起——给手机发 carInfo、手机切成 USB 网卡后给电脑这边的网卡配 IP——**不归本程序**，
由维护者自己的脚本完成。本程序只负责：在网卡就绪之前先把控制监听开好；手机连进来之后，完成剩下的一切。

## 准备

- JDK 17。
- 连接参数 JSON：和构建安装包用的是同一份 `openhc-identity.json`（不在仓库里，格式见 `docs/identity.example.json`）。
- 一个放信任库的目录（不存在会自动以 0700 新建）。

## 运行

推荐先打成可执行目录再运行（Ctrl-C 能直接送到程序，按协议收尾）：

```sh
./gradlew :tools:desktop:installDist

tools/desktop/build/install/openhc-desktop/bin/openhc-desktop \
  --identity <你的 openhc-identity.json> \
  --trust-dir ~/.openhc-desktop/trust \
  --ip 192.168.66.150 --port 32400 \
  --bt 02:12:34:56:78:9A \
  --width 1280 --height 720 --fps 30 \
  --video-out /tmp/openhc-$(date +%Y%m%d-%H%M%S).h264 \
  --carinfo-out /tmp/openhc-carinfo.bin
```

也可以经 Gradle 直接跑（相对路径按仓库根目录解析；Ctrl-C 经 Gradle 转发，不一定能按协议收尾，
需要固定时长时用 `--duration`）：

```sh
./gradlew :tools:desktop:run --args="--identity … --trust-dir … --ip 192.168.66.150 --port 32400 --bt 02:12:34:56:78:9A --video-out /tmp/out.h264 --duration 120"
```

`--help` 列出全部参数：

| 参数 | 说明 |
|---|---|
| `--identity <文件>` | 身份资产 JSON（必填） |
| `--trust-dir <目录>` | 信任库目录（必填） |
| `--ip <IPv4>` | 车机在 USB 网卡上的地址，正好 14 个字符（`192.168.66.100`～`192.168.66.253`），写进 carInfo（必填） |
| `--port <端口>` | 控制监听端口，写进 carInfo（必填） |
| `--bt <AA:BB:CC:DD:EE:FF>` | 车机蓝牙地址，可以是合成值（必填）。不要用 `02:00:00:00:00:00`，那是「取不到」的约定值 |
| `--video-out <文件>` | H.264 输出文件，不能已存在（必填） |
| `--carinfo-out <文件>` | 把 91 字节 carInfo 原样写到这里，给 USB 拉起脚本用（0600，原子覆盖） |
| `--width` `--height` `--fps` | 声明给手机的画布宽高与帧率，默认 1280×720、30；屏幕刷新率不是 60Hz 时帧率按实际填 |
| `--dpi` `--density` | 默认 160、1.0 |
| `--gop` `--bitrate` | 声明关键帧间隔、目标码率（bit/s），默认不声明 |
| `--bind-ip <IPv4>` | 控制监听绑定的地址，默认 `0.0.0.0` |
| `--local-filter on\|off` | 通配监听时是否只接受连到 `--ip` 的连接，默认 `on` |
| `--duration <秒>` | 运行这么久后自动结束 |

## 一次运行的过程

1. 读身份资产，打开信任库，生成 carInfo 写到 `--carinfo-out`，建好视频输出文件。
2. **先开控制监听**，看到下面这行再开始 USB 拉起：

   ```
   ================================================================
     可以开始 USB 拉起（发 carInfo，给手机网卡配 192.168.66.150/24）
   ================================================================
   ```

3. 外部脚本：经 USB 控制传输发 carInfo（请求类型 0x40、请求 0x34、值 0、索引 0xA0、91 字节）；
   手机切成 USB 网卡后，给电脑这边的网卡配上 `--ip`/24。手机随即来连控制端口。
4. 本程序跑完控制通道 → 认证 → 设备会话 → 投屏 → 收视频。首次配对时醒目地打印 6 位连接码，在手机上输入；
   配对成功后写进信任库，之后同一身份（同一份身份资产、同一个 `--bt`）再连就免码回连。
5. 手机断开、出错、`--duration` 到期或 Ctrl-C 时结束：投屏层先发 TEARDOWN，再由上到下关闭全部连接，最后打印统计。

**控制监听为什么绑通配地址**：开监听时手机还没切成 USB 网卡，`--ip` 这个地址在电脑上还不存在，绑不上；
手机配好网卡后几乎立刻就来连，等网卡就绪再开监听来不及。所以默认绑 `0.0.0.0`，但只接受本端地址是 `--ip`
的连接，从别的网卡连进来的直接关掉。之后的认证、业务 20、设备控制监听都在会话中途才开，那时网卡已就绪，
直接绑在 `--ip` 上。网卡事先就绪时也可以用 `--bind-ip` 直接绑 `--ip`。
万一日志里出现「本端地址不是 … 的连接，已关闭」而那确实是手机，可以加 `--local-filter off` 关掉筛选
（代价是别的网卡上也能连到控制端口，只能靠后面的认证把关）。
macOS 开着防火墙时，第一次监听通配地址可能会弹窗询问是否允许 java 接受传入连接。

## 输出

- **视频**：Annex-B 格式的 H.264（带起始码），帧按收到的顺序原样拼接，文件权限 0600，不覆盖已有文件。
  可以用 `ffplay -f h264 文件` 或 `ffprobe` 查看。
- **统计**（结束时打印）：结束原因、视频帧数、关键帧数（含 IDR 片的帧）、字节数，
  首帧耗时（从手机连上控制通道到收到第一帧，以及从手机接受 PLAY 到第一帧）。
- **日志**：每行带时刻和启动后的秒数，写清每个阶段。不打印密钥、会话密钥、完整设备标识：
  本机 deviceId 只显示前 4 位，不打印蓝牙地址和手机的认证身份；连接码只在首次配对时显示一次。

退出码：收到了视频帧为 0；参数或启动失败为 1；会话结束但没收到视频帧为 2。

## 信任库

- 目录权限 0700，里面一个文件 `trust-store.bin`（0600），内容是 core:auth 的版本化格式，含本机长期身份的私钥。
- 首次配对成功时整份重写：先写同目录的临时文件并刷盘，再改名覆盖，写一半断电也不会坏。写不进去时这次配对按失败处理。
- 已有的目录或文件不属于当前用户、权限不对、是符号链接、内容损坏或版本不认识，都直接报错退出，不擅自改权限，也不当成空库。
- 换了 `--bt` 或身份资产里的车型，就是另一台车：本机身份对不上，手机会要求重新配对。
